# 龙岗图书馆多账号签到

## 安装与获取账号

模块和脚本发布到 GitHub 后，在 Surge 添加：

```text
https://raw.githubusercontent.com/byhooi/Surge/main/Module/lggov_sign.sgmodule
```

1. 使用 Surge iOS 5.9.0 或更新版本，开启 MITM、安装并信任证书，确认 `tsg.lggov.cn` 被解密。
2. 在微信内正常打开龙岗图书馆网站并登录，进入“我的”页面，等待“已添加签到账号”通知。
3. 依次切换其他已授权的读者证或登录其他账号，每次都进入“我的”页面。每张读者证独立保存，同一证号更新 Token，不重复新增。
4. 定时任务默认按设备时区每天 8:20 签到、每天 0:15 / 12:15 查询个人信息尝试续期，可在模块参数中修改。已安装旧版模块时，请检查“定时续期”参数是否仍保留旧值，必要时改为 `15 */12 * * *`。
5. 可在 Surge 手动运行“龙岗图书馆签到”或“龙岗图书馆续期”；BoxJS 订阅更新后也可手动签到、手动续期和管理账号。

无需手动复制 Token，也不从 HAR 导入任何真实凭证。仓库文件未发布前，raw 链接不会包含本地改动；可先将脚本导入 Surge 本地测试并调整模块中的脚本路径。

## Token 到底多久过期

已分析的签到响应中，JWT 的 `exp` 比响应时间晚 **60,000 秒，即 16 小时 40 分钟**。这只是当前样本观察到的有效窗口，不是服务端对所有 Token 的保证。

- 同一次请求与响应相比，响应 Token 的到期时间向后延长了 5 秒，说明至少这个响应更新了凭证有效期。
- Token 未包含 `iat` 签发时间，不能据此还原所有 Token 从登录开始的固定寿命。
- JWT 还含 `sz_token_expires_at`。样本中该时间已经过去，但图书馆签到仍返回成功，因此不能拿它代替外层 JWT 的 `exp` 判断本接口有效性。
- 网站前端会保存响应头中的 `Authorization`，本脚本同样保存，不自行生成或修改 Token。
- 单纯每天使用一次 Token，24 小时超过已观察到的有效窗口，因此默认增加每 12 小时一次的个人信息查询，减少后台唤醒次数。相对样本有效窗口留有 4 小时 40 分钟余量，漏执行仍可能导致过期。

**续期是待实机验证的维持登录方案，不是永久免登录承诺。** `GET /userHub/opac/reader/info` 是否持续延长有效期、是否有服务端绝对会话上限，仍由网站决定。续期任务会比较前后到期时间；未观察到延长时发出提醒。没有抓到独立的 refresh-token 接口，脚本不会伪造该接口，也不会用已过期凭证反复尝试。

设备关机、Surge 停用、后台任务未执行、退出/重新登录使旧会话失效等，都可能导致保存的账号不可用。此时需要重新登录对应账号并进入“我的”页面。切换读者证是否会使前一个账号的 Token 失效也需要实机验证；按账号分别保存不能绕过服务端的会话限制。

## 请求与结果判定

| 用途 | 请求 | 行为 |
| --- | --- | --- |
| 签到 | `POST https://tsg.lggov.cn/userHub/opac/login/points` | 携带该账号 Authorization，无请求体 |
| 续期/积分查询 | `GET https://tsg.lggov.cn/userHub/opac/reader/info` | 保存有效响应 Token，读取总积分 |
| 自动捕获 | 个人信息、登录、切换读者证和签到接口的响应 | 优先读取响应头中的 Token，不修改网页响应 |

签到业务 `code === 0` 且 `data` 为 `true`、`1` 或 `"1"` 时，与网页行为一致，记录为成功。`false` / `0` / `"0"` 只提示“未发放积分，可能今日已签到”，不假定成功；其他返回值提示未知。

成功后查询总积分，不把 `true` 解释成“加 1 分”。若已由此脚本确认当日成功，后续手动签到会按北京时间日期跳过，定时续期仍正常运行。浏览器自动签到不写入这个本地成功标记，因此首次手动执行可能遇到当天已领取的结果。

多账号按最近处理时间从早到晚逐个执行，一个账号失效不阻止后续账号。任务带短期锁，避免常见的签到/续期重叠；Surge 存储不提供跨脚本事务，不要同时手动启动多个任务或在任务期间编辑账号列表。请求不自动重试，不自动跟随重定向，不使用共享 Cookie，以减少重复提交和串号风险。整个任务预留 90 秒执行窗口、每次请求 12 秒超时，每轮最多处理 30 个账号以控制原生引擎计时器数量；账号很多或网络慢时会通知未处理的账号，可稍后手动执行，未处理账号会优先排到前面。

## BoxJS 管理

点击“手动续期全部启用账号”即可立即执行一次个人信息查询并保存返回的 Token，**不会提交签到，也不会改变每 12 小时的定时安排**。它是一次性操作按钮，不是自动续期的启停开关。

手动续期无论成功或异常都会通知各账号结果；成功时显示新的北京时间到期时间。没有账号、任务正在运行或凭证已过期时也会提示。定时续期仍只在异常时通知。已过期的 Token 不能靠按钮恢复，需要重新登录捕获。

手动签到/续期按钮设置了 120 秒执行超时。建议在 BoxJS 配置好 Surge HTTP-API；若使用 BoxJS 内部执行模式，仍受 BoxJS 所在脚本自身超时限制。更新仓库文件后需刷新 BoxJS 订阅，确保两个入口脚本都已发布。

在订阅中的“龙岗图书馆多账号签到”查看 `byhooi_lggov_accounts`，它是 JSON 数组：

- `cardno`：账号标识，不要手动修改。
- `token`、`expiresAt`：自动维护的凭证及毫秒级到期时间，不要手动修改。
- `enabled`：改为 `false` 可停用该账号，自动捕获不会重新启用它。
- `lastSignDate`：最近一次由脚本确认成功的北京时间日期。
- `lastResult`、`totalPoints`：最近运行结果和最后查询到的总积分。

删除整个账号对象即可移除；保存 `[]` 可清空全部账号。已移除账号若再次浏览对应网页，会重新被捕获。任务锁由脚本自动清理，异常中断后 150 秒失效。

账号列表包含读者证号和登录凭证，不要截图公开、分享 BoxJS 备份或提交到 Git。日志和通知只显示证号后四位及结果，不输出完整 Token、服务端原始正文或个人资料。

## 本地验证

```text
node scripts/build-lggov-refresh.cjs
node --check Script/lggov_sign.js
node --check Script/lggov_refresh.js
node --test tests/lggov_sign.test.cjs
```

`Script/lggov_refresh.js` 是由主脚本生成的独立手动续期入口，不依赖 BoxJS 传入参数，也不动态下载/执行代码。修改业务逻辑时仅编辑 `Script/lggov_sign.js`，再运行生成命令并一起发布两个文件；测试会检查生成文件与主脚本同步。

测试通过 Node 内置虚拟环境模拟 Surge、账号和 HTTP 响应，不访问真实网站，不读取真实 HAR。不能替代手机上的 MITM、后台定时、账号切换与跨日续期验收。

实机建议：捕获两个已授权账号，核对 BoxJS 有两项；运行一次续期检查两者到期时间是否延长；运行签到核对积分明细；次日检查后台任务和登录状态。不要为了测试反复提交签到请求。

Surge HTTP 客户端选项及最低版本参考：[官方 JavaScript API](https://manual.nssurge.com/scripting/api.html)。
